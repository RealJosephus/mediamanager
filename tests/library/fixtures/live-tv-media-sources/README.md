# Read-only Live TV media sources

`Program.cs` executes the current designated build's actual `DefaultLiveTvService.GetChannelStreamMediaSources`, `TunerHostManager`, `LiveTvMediaSourceProvider.GetMediaSources` (including its private `Normalize`), `MediaSourceManager.GetDynamicMediaSources` / `SetKeyProperties`, and public `GetPlaybackMediaSources`. It creates actual typed `LiveTvChannel`, `User`, permissions and `UserItemData`, and captures the actual `BaseItemMapper.Map` row. It does not duplicate these algorithms in a C# oracle loop.

The default service's constructor subscribes to recording timers. The fixture instead initializes its actual reader dependencies on an uninitialized instance; it does not construct a timer manager or subscribe to `TimerFired`. Its tuner is a declared response control with a guard against every stream-opening or discovery executor. `IRecordingsManager` returns no active recording and rejects every other method. Native user-data lookup and the small English/Chinese/Japanese language lookup are declared controls. The real user configuration, permission checks, channel `EnableRememberingTrackSelections=false`, default-track selectors, source sorting and placeholder filtering execute. The manager is constructed and disposed normally, its open-stream dictionary stays empty, and every cancellation owner is disposed. `allowMediaProbe=false` prevents metadata probing; `enablePathSubstitution=true` skips native filesystem symlink resolution. No recording, tuner stream, encoder, media download or probe starts. No native EF/SQLite database is opened in this component.

Each case records four distinct states: real static placeholder, direct provider result/error, manager-prefixed dynamic result/error, and the final playback result/error. The direct provider does not add its own type hash. The manager independently adds that hash to both nonempty `OpenToken` and `LiveStreamId`, preserving an existing prefix without regard to case. `RequiresOpening` first replaces a caller token with `LiveTvChannel_<channel GUID N>_<original source ID>`; an absent source ID leaves the final separator. Even a retained token with `RequiresOpening=false` gets the manager prefix. The direct states are retained as raw evidence; Node's `LiveTvMediaSources` represents the combined provider/manager dynamic boundary and is compared with that dynamic state.

Input objects are sparse CLR DTO declarations. Before any normalization, the oracle snapshots their real constructor/deserializer result into `preparedSources`. Node's declared tuner callback supplies an owned copy of that exact input frame. This avoids inventing a second DTO constructor implementation in the fixture, while all expected normalized and playback values come from separate real native method executions. These controls intentionally include values such as missing HTTP path or null source identity to exercise the consumer's actual contract; they do not claim that the separate Node SDK source validator accepts those declarations. Tuner/SDK producer validation is covered by its own component evidence.

Node imports the exact actual mapper's persisted columns and JSON into a fresh PostgreSQL schema, constructs real `LibraryService`, `ItemCreationService` and `PostgresLinkedChildrenStore`, and cold-loads each channel through the real item cache. The production `LiveTvMediaSources` performs discovery, normalization, fallback and key assignment. Its fallback uses actual typed item lookup and `LibraryService.getLiveMediaSources`. The production static-source function reads its real SQL state and user data. The final `LibraryService.getMediaSources` independently queries the retained channel and SQL `UserData`, applies default tracks and playback permissions, sorts sources and filters placeholders. User identity, policy and preference objects are declared consumer controls; this is not native/Node authentication or HTTP binding evidence.

Cases cover TV/radio dummy tracks, unknown technical values, duplicate stream indices, external-stream exclusion from total bitrate, explicit zero total bitrate, unchecked int32 sum overflow, buffer defaults and explicit zero, missing HTTP input, retained and replaced opening tokens, case-insensitive key prefixes, empty/unimplemented fallback, non-fallback exceptions, null stream collections, unavailable service, retained nonempty channel path, provider-ignored cancellation, preferred identity/file type/3D/width/stable ordering, five subtitle modes, original audio language, persisted channel selections that must be ignored, all eight video permission combinations and two radio permission combinations. The complete selected source/stream field contract is explicit in `input.js`; computed display titles, codec capabilities and unrelated DTO fields are outside this slice. Suppressed errors compare their presence/count at the dynamic boundary; native exception types and Node diagnostic types/messages are both retained rather than relabelled as the same runtime exception.

An additional real PostgreSQL lifecycle case holds the tuner callback, starts `close`, proves later operations reject with 503 and the caller signal remains un-aborted, then releases an empty response. The already-admitted task completes its actual SQL-backed static fallback before close resolves. All gates release in `finally`. Each normal and held case checks library rows, user-data rows, users, permissions, preferences and stream rows remain unchanged; SQL item-state and cohort owners must be released. Final cleanup closes every source owner, item cache, library, SQL links, schema, store and pool, and verifies protected native reference inputs via `currentNativeReference.finish`.

The actual native third-party `Normalize` variant is captured separately. It forces transcoding, fills blank video `NalLengthSize` with `0`, and assumes interlaced video; the default-service variant does not. This is native-only observation, not a claim of an implemented Node third-party service producer.

Input/output hashes, executing assemblies and exact build source bindings are retained under the authorized validation directory. This is component evidence for read-only default-service media sources; it does not establish HTTP playback, actual stream open/close, recording, phase or release acceptance. Execute only in the authorized Actions workflow.
