# Latest media inputs

The current specified Jellyfin build, started from a private stopped instance,
records both latest-media routes for these inputs on every comparison run.
No response is synthesized from candidate output or a replacement Emby server.
Collection folders have real native `.collection` files; startup's resolved
type must equal the declared input before the Node comparison can proceed.

The 67 entities and 130 HTTP observations cover movie presentation keys and
equal dates, hidden owned items and alternate versions, album selection and album access, TV single-season/multiple-season
containers, the inclusive 24-hour boundary at 100 ns precision, played defaults,
the early grouping stop and negative limits, root exclusions and explicit parents, UserViews, ungrouped results, limits,
DTO options, ignored query members and binding errors. Complete successful
arrays and error bodies are compared; only isolated server identity,
ProblemDetails trace identity and equivalent UTC date formatting are projected.
Database and filesystem snapshots must remain unchanged after reads/shutdown.

Sources: the designated `UserLibraryController.GetLatestMedia`,
`UserViewManager.GetLatestItems/GetItemsForLatestItems`,
`LibraryManager.SetTopParentIdsOrAncestors` and the locally modified
`BaseItemRepository.Querying.GetLatestItemList`. Build/input identity, original
HTTP, complete rows, comparison and private cleanup receipts are retained by
the current native reference harness in the validation artifact.
