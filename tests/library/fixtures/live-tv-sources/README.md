# Retained tuner and listings management

`Program.cs` invokes the selected native build's actual `TunerHostManager`, `ListingsManager`, private EPG channel matching consumers and `MyXmlSerializer`. Each case has an isolated actual configuration XML file and actual tuner/XMLTV cache marker files. The configuration-manager save boundary, guide queue and tuner/listings providers are declared controls. Save and refresh failures are deliberately injected there; this is a manager component differential, not an actual native HTTP server or full guide refresh.

The Node side installs the fixture package through the real `PluginHost`, obtains only formal `tuner` and `listings` entries, and uses the real `LiveTvService`, inheriting XML I/O, named caching, admission and shutdown from `src/core/live-tv-configuration-store.js`. The configuration model and reader/serializer are core infrastructure; the library subclass retains user and guide business behavior. Provider calls assert the plugin-owned cancellation signal. Comparisons preserve call order, mutated input, current configuration cache, configuration reloaded from XML and cache deletion, including failed validation/save/refresh prefixes. Independently generated native and Node IDs must be lowercase Guid N values and receive ordinal comparison labels; later operations resolve each side's own generated ID.

Cases include supported type sorting under explicitly fixed native `en-US`, discovery filtering and swallowed host failures, URL-change scans, cloned tuner validation versus in-place listings validation, empty and null configuration arrays, default fields, update/append/delete, safe cache paths, lineup selection, duplicate EPG channel winners, program/metadata cache reuse and invalidation, mapping priority, repeated identical mapping removal, and failure after an already saved mapping. Production type sorting accepts the current request culture callback; this oracle establishes the `en-US` sample only.

An additional native typed JSON probe constructs real MVC `JsonOptions` and copies the exact JSON settings in `ApiServiceCollectionExtensions`, then calls the actual native model serializer and required data annotations. It compares defaults, property casing, duplicate token failures, nullable arrays/entries, string token conversion and required mapping fields. It does not execute MVC input formatters, authentication or native HTTP response formatting. `tests/http/live-tv-sources.test.js` separately checks action registration, real authorization policy evaluation, typed body dispatch, typo alias, SHA1 password/query conversion and country byte response with a controlled action service. Real HTTP differential acceptance remains separate.

`live-tv-sources-close.test.js` pauses an installed provider inside actual mutation admission, then closes source/configuration/recording-folder owners. It covers validation success/failure with and without an observer, successful child save consumption, cancel-only root reservations, released capabilities, refusal of new work, real XML handles and dependency-permit release. The library admission implementation in this test is an explicit counted control; it does not establish PostgreSQL timing or native shutdown timing.

Reports bind source files, input/output SHA256 and executing assembly hashes. Owners close before isolated private configuration/cache/plugin files are removed. No stream, recorder, scheduler execution, encoder or native hardware executor starts. These tests do not establish full guide persistence, Schedules Direct country transport, phase acceptance or release acceptance. Run only through authorized Actions validation.
