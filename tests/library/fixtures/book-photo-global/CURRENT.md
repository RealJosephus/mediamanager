# Current Book/Photo global scan consumer

`book-photo-global.test.js` now obtains both complete Native observations from the designated build supplied to the same Actions run. Historical `provenance.json`, raw references, projected `native.json`, source helpers and assets remain unchanged and are not execution prerequisites. `current/input.json` is an exact byte copy of the original matrix: fourteen cases, sixty-one scan steps and eight assets. Its historical absolute asset names are descriptive; the current project resolves only their basenames under the separately bound `current/assets` directory and verifies every byte count and SHA-256.

The current project retains actual CoreAppHost resolver discovery, LibraryManager roots and complete traversal, Book/Photo metadata services and local providers, image saving/Skia, EF SQLite persistence and independent repository reads. Each capture creates fourteen separate case directories. The helper executes the entire matrix twice in separate processes/state directories; it compares functional results only after retaining both full records. Source ZIP bindings, supplied runtime manifest identity, loaded managed assemblies, the actual SQLite/Skia imports, project/build/process/output hashes and completed resource release are recorded. No historical expected output is used to produce either capture.

The existing `book-photo-global-runtime.test.js` remains a separate contract. That fixture disables Node NFO/TMDB and gives copied media/comics a declared past mtime window. This consumer preserves the original default Node plugins, Windows logical identity, independent original/sidecar mounts, media-side decoy XML, and actual current filesystem write times. Both Native hosts historically registered no metadata savers; this current host keeps that control. It does not disable Node savers, substitute metadata calls for scans or insert extra refreshes.

Photo replacements have an explicit real-time input condition: before overwriting an existing photo, both hosts wait until the actual clock passes that file's previous mtime plus 1.1 seconds, then write the replacement normally. The extra 0.1 second keeps filesystem/clock precision away from the public one-second photo change boundary. No past/future mtime is assigned to prepare this condition. Each mutation records the previous/new actual mtimes, the waiting interval and its deadline. All fourteen cases, sixty-one scan steps, eight assets and original matrix bytes remain fixed, with exact functional comparisons after equivalent replacement time inputs.

All original comparisons remain: path/type/name/folder/media type, parent/ancestor relations, series/index/overview/genres, dimensions, image kind/location/extension/BlurHash and SHA-256. Actual image bytes are additionally compared. Every step still invokes one formal complete scan, including malformed EPUB/photo inputs, their persisted failure prefixes and subsequent repair scans. The original successful outer-scan requirement remains; internal provider errors and CLR/Node exception classes are diagnostics. Scan-before and scan-after full business tables, cold Native reads, file bytes/hashes and timing evidence are retained even when the public comparison fails. Missing images immediately after an input removal can be recorded in the pre-scan prefix; post-scan image reads keep the original strict consumer behavior.

The whole SQL records are evidence, not an all-column equivalence claim: independent state roots, generated IDs and wall-clock values differ. The functional projection uses item paths as identity roles; it preserves image order and the ancestor relation set. ZIP container encoding/timestamps are not compared, while their input entry names/content and extracted image bytes remain fixed.

The Native host retains explicit monitor, two post-scan sentinel and external-cleanup controls. This slice does not replace the actual monitor/post-task contracts, a complete Native server/HTTP handover, full-database exchange, production-scale coverage or final release acceptance. Native case files stay in the isolated validation artifacts. Node closes each runtime, drops its exact fresh PostgreSQL schema and removes only its own temporary directory after preserving evidence; cleanup receipts are mandatory.

Run through GitHub Actions with `native_reference=true` and services `dotnet`, `jellyfinDll`, `postgres`. The exact migrated consumer is `tests/library/book-photo-global.test.js`; the independent `tests/library/book-photo-global-runtime.test.js` may be scheduled separately. No local test, syntax check or build is part of this migration.
