# Current native identity lookup scenarios

`tools/compat/identity-side-effect-input.js` defines the original Artist/Studio
names and schedules: eight concurrent equal-name lookups and repeat, Unicode
creation/list/repeat, and five two-name collision schedules (two repeated pairs,
reverse pair, eight requests, reverse eight requests). The candidate executes
the same requests against its actual PostgreSQL runtime. The native recorder
uses a private clone of the workflow's stopped instance and bound native build.

There are 90 original HTTP observations per platform. Four additional native
single-name controls independently observe both colliding names' complete rows.
A concurrent winner on each side must be one of these genuine native results;
the two processes need not pick the same winner. All 72 persisted columns,
unique identity/row/directory, existing rows and relationships, complete HTTP
responses, Unicode SortNames, repeated reads, shutdown, and cleanup are checked.
Only separately bounded creation clocks, equivalent physical path separators,
GUID representation, native boolean representation, and individually bound
server IDs are projected. Raw reports remain available before comparison.

The recorder discovers identities from newly inserted native rows; it does not
import the candidate identity functions or select native rows by predicted IDs.
Private instance bytes and credentials are excluded from published artifacts;
report credential fields are represented by SHA-256 markers. Historical raw
recordings and seals are unchanged. This current comparison does not revalidate
the missing historical executable and recording trees.

The conflict matrix retains the original four requests per kind, in order:
blocked file, first normalized name, same-path name, and wrong-type primary key.
A separate disposable native discovery run observes all input IDs and metadata
paths. Only those observed identities seed a regular blocked file and a Movie
at the Shadow ID in the stopped conflict clone; no candidate identity algorithm
chooses the native precondition. The candidate checks every new/replaced column,
all earlier rows and relationships, exact blocked-file bytes, actual directory
creation/modification clocks, and shutdown. Type, runtime, added-field, date,
and file-digest negative controls are retained.
The controlled base Movie retains the stopped native seed's `Synthetic Movie`
name and SortName, including when a blocked directory makes the filter return it.
