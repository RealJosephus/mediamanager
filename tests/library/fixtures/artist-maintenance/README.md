# Artist batch lookup and maintenance inputs

This records the designated ArtistsPostScanTask, ArtistsValidator, LibraryManager,
LinkedChildrenService, BaseItemRepository and EF SQLite persistence. The metadata
provider is controlled. No media or HTTP port is opened. Program.cs, the project,
input and recording bytes are bound by provenance.json to the designated source,
actual assemblies and SQLite runtime; the build input closure remains incomplete.

The 36 cases include 34 maintenance scenarios and two separate-save ordering
counterexamples. Every before/after BaseItems row includes all 72 columns. The
SQLite insertion sequence is independent input alongside batch lookup winners,
relations, files, refresh calls, progress, cleanup and failure observations.

native-item-order.test.js currently verifies insertion order, preferred Artist
selection, reopen, PostgreSQL/SQLite exchange and runtime SaveItems batches.
Constructor inputs for runtime saves are reconstructed from the recorded sample
parameters and the original constructor code, independently of resulting rows.
artists-post-scan.test.js separately consumes the complete before rows, relations
and files to compare task refresh calls, shared state, failure prefixes, cleanup
and every after column. It includes the eight refresh-state/ observations, bounded
PostgreSQL pages and the candidate's actual metadata host. Providers remain
controlled in the native recordings; these checks do not claim the complete
native metadata provider/client lifecycle or final library scan acceptance.

The reverse/ recording adds two actual native batches whose dependent items are
supplied before their parent/owner. Its source, input, recording and provenance
bytes remain separate. Candidate SaveItems and exchange verify all 38 observations.
