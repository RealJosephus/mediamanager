# Ordinary Video deletion with external alternate versions

The current supplied assemblies execute the actual `LibraryManager.DeleteItem`,
`ChannelManager.DeleteItem`, typed Video methods, repository, linked-child
service and EF SQLite persistence. A fresh component-owned database preserves
the actual placeholder seed. Its complete initial BaseItems and LinkedChildren
rows are copied into a fresh PostgreSQL graph. This is component evidence,
not production SQLite migration/import or a full native HTTP host.

The primary is an ordinary Library Video. Local and linked alternate Videos
retain an external Channel identity. Actual SQL relations select the alternates;
one input clears both unsaved primary arrays after those relations are committed.
Missing alternates run the actual recursive deletion. An explicitly false outer
`DeleteFromExternalProvider` flag does not carry into the fresh recursive native
`DeleteOptions`, whose provider flag defaults to true. Existing alternate source
bytes instead take the real promotion path without deleting the provider item.

Provider callbacks are controlled and reject every external identifier except
the two declared owned inputs. Success, ignored ArgumentException, first failure
and failure after an already committed deletion are observed separately. Actual
provider, external-data cleanup, SQL persistence and ItemRemoved event prefixes
include the live entity fields, rows, lookup visibility and metadata files at
each boundary. A controlled read-only media-source dependency supplies empty
streams and attachments, and a segment dependency reports unsupported. Actual
`MediaSourceManager.GetPathProtocol` and `SupportsDirectStream` evaluate the
real path/protocol capability with the actual `ManagedFileSystem`; every
execution method remains forbidden at the component boundary. These queries
are required by `BaseItem.GetVersionInfo` during metadata-path enumeration.
Actual
BaseItem/Video media-source enumeration and Channel saved-cache fallback still
run. No catalog fetch, recording, tuner, encoder, media probe or live stream
executor starts. All source bytes remain in the fixture-owned directory.

Native provider callbacks receive the actual CancellationToken.None. Node
separately records its real PluginHost activation signal; these are not labeled
as the same cancellation object. Node runs actual typed entities, PostgreSQL,
ItemCreationService, ItemDeletionService, MetadataRefreshHost repository updates,
ExternalDataManager and mapped I/O. Only each external-data marker directory is
controlled; its deletion service and filesystem operations remain real.

Two Node lifecycle cases pause the primary's first metadata context after
synchronous provider admission. Channel close and metadata cancellation start
before the SQL version consumer reaches its provider. That consumer must finish
using the single admitted operation for either outer flag, reject new admission,
preserve source bytes, release all relation states/cohorts and drain before
dependency closure. These cases do not claim a matching native shutdown host.

The packaged SQLite image for the SDK's current RID is explicitly loaded and
installed as the provider resolver before initialization; its path, RID and
SHA-256 are recorded alongside actual managed assemblies, input bytes and source
bindings. Only componentAcceptance can become true after every comparison and
hard assertion succeeds. Phase and final release acceptance remain false.
