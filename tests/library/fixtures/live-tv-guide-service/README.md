# Guide refresh orchestration

The component uses actual PostgreSQL, global Live TV UserView creation, typed channel/program entities, captured SQL cohorts, complete GuideProgramBatch persistence, MetadataUpdateHost, MetadataRefreshHost and ordinary ItemDeletionService. Controlled external service methods provide channels/programs; recording-directory and device-scan dependencies record their call boundary. Image precache is a controlled retained-view consumer, separately implemented and verified by the guide image fixture. These observations do not claim actual native GuideManager orchestration or full HTTP/provider execution.

Cases cover channel persistence before the first program request, clamped guide dates, complete new/updated batches, ForceSave channel metadata, additive Kids tags, database-only stale channel deletion, no cleanup after a channel error, no early program save on late materialization failure, and close/cancellation draining of a late external service with configuration admission and SQL ownership released. The real native materializer differential, raw stream consumers, provider files/HTTP, timer execution and release acceptance are separate scopes.

Sources: the designated `D:/jellyfin/src/Jellyfin.LiveTv/Guide/GuideManager.cs`, `MediaBrowser.Controller/LiveTv/LiveTvChannel.cs`, `Emby.Server.Implementations/Library/LibraryManager.cs` and the shared repository persistence/deletion contracts under the project GPL license. Recording timer refresh is deliberately absent because built-in recording execution is removed. No fake timer refresh callback is invoked.
