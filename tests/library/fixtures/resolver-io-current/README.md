# Current resolver IO boundary capture

This new component captures the three unchanged neutral resolver IO scenarios
with two independently built/executed oracles in the current Actions job. Each
capture owns a fresh real filesystem, LibraryManager, CoreAppHost-discovered
resolvers and SQLite repository. The forwarding filesystem injects exactly one
named IO failure. All surviving items, persisted path-derived identities and
the failure boundary are compared with the Node resolver pipeline.

The same-run designated source offer, complete runtime and isolated SDK byte
receipts bind the execution. The actual loaded platform SQLite RID and file
are checked against the exact runtime member. Inputs are byte pinned here;
the original resolver-io-boundary recording and its incomplete historical seal
are preserved and are not read by this consumer.

Original stacks, initialization clocks and diagnostic log counts remain in raw
captures. Independent repeat checks compare complete item results, parent
values and the actual named fault boundaries. Candidate observations
retain the actual fault, reads and surviving item order. This isolated test
does not establish a whole library scan, HTTP exchange, phase or release
acceptance. Build and execute only through the repository Actions workflow.
