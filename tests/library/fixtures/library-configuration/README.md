# Native virtual library creation

The neutral input executes the designated build's actual `LibraryManager.AddVirtualFolder` and `GetVirtualFolders`, actual `CollectionFolder` options cache/XML persistence, actual `ManagedFileSystem` shortcut creation and real instance files. Structural roots, provider, directory invalidation, monitor and scheduled-task admission are controlled. The returned folder IDs use the actual native identity function.

The 44 cases cover naming and collisions, path placeholders, collection markers, Unicode location ordering, live options and reopened XML, content-type cleanup, partial failures, monitor/finally order and refresh admission. The candidate compares files through native XML consumer semantics, complete options, folder results, failure presence and call order. Path substitutions and GUID identity are retained. XML whitespace and CLR exception labels are diagnostic. Candidate-produced files are retained for a subsequent native consumer read.

The supported-platform name contract rejects a whitespace-only sanitized name or a selected directory name ending in a dot or space before changing files or stopping the monitor. Three cases exercise this intentional validation difference from the Windows native creation result. Node can create literal Windows file-namespace names that the actual native directory consumer cannot reopen; reproducing Windows directory normalization would make the product contract depend on the host platform. The remaining 41 cases compare the complete native creation result. All 44 candidate output states are independently reopened by the actual native folder and options readers.

This recording was made on Windows. Declared Windows/POSIX identity tests and portable Node implementation do not replace executing the platform matrix. This fixture does not prove HTTP binding/authorization, rename/removal/path-edit actions, full scanning, real watcher behavior, PostgreSQL lifecycle or either Web client. Those require independent integration evidence. `candidateVerified:false`, `completeBuildInputClosure:false` and `phaseAcceptance:false` describe the native recording. Exact source/build copy, oracle and runtime identities are bound by `provenance.json`; Jellyfin sources are GPL-2.0.

Reproduce with the pinned `MEDIAMANAGER_JELLYFIN_DLL` and `MEDIAMANAGER_DOTNET`, `tools/validation/oracle.js`, this project and a fresh output directory. Arguments are the input JSON, fresh state directory and native result destination.
