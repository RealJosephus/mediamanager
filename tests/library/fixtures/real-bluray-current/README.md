# Complete original Sintel Blu-ray consumers

The explicit `bluray_reference` CI promise supplies the complete official
1,593,180,160-byte Sintel ISO with SHA256
`693ac48a9ecc53071d014ef485d7850f916abef624c8dafa1d5801d828158c69`.
Each host acquires and independently rereads that original, uses its actual
7-Zip UDF reader to list, test and extract the entire disc, and matches every
original member against the first complete acquisition. All 14 BDMV files,
including both original M2TS files, remain intact. The full input is required
before and after each consumer; old Linux receipts, missing payloads and empty
BDMV directories cannot replace it. Windows binds its actual `7z.dll` as well
as its executable; the source service records the same candidate/run/attempt,
platform, actual Node executable, reader and producer files.

`real-bluray-components.test.js` executes this Oracle against the designated
Native runtime assemblies. `Program.cs` uses the real ManagedFileSystem,
BDROM/BdInfoExaminer and MediaEncoder, with the same fixed ffmpeg/ffprobe inputs.
Every original source file is fully hashed. The actual selected M2TS files are
probed through the designated fork's LocalMediaProxy. Native repeats this
observation in its own process. The independent Node side uses a read-only Local
VFS, its production Blu-ray planner and actual ffprobe bridge; playlist, clips,
timestamps, chapters, declared BDInfo stream fields and full probe stream/chapter
values compare against Native. Original Native JSON, assemblies, process
receipts and Node results remain available in the component report.
The report retains the exact input and both original component JSON byte
sequences as base64 with their sizes and hashes before parsing or comparison.
These component-only observations contain file/probe values and no server
authentication session. The public report remains self-contained after private
working directories close, including when a later comparison fails.

All three BDInfo stream types compare the actual model's nonnullable
`IsInterlaced` and `IsHearingImpaired` values. CLPI video interlace values remain
authoritative. Selected chapter timestamps also create actual Native
`ChapterInfo` objects: their full constructor observations remain in the capture,
and Node compares their positions and default `ImageDateModified` at exact tick
precision. Chapter persistence uses the native MinValue database text. The
complete original first-scan consumer in run `40525661944` reached both actual
scans on all three platforms and found these three persisted default-value
differences; its original failed reports remain unchanged. These values are
fixed in the Blu-ray merge rather than removed from technical-row or public DTO
comparisons.

This first slice establishes source supply and component differences. It does
not claim a server scan, PostgreSQL/SQLite exchange, complete-library,
complete-instance, menu decoding, commercial/encrypted Blu-ray, or release
acceptance. The observed HDMV, absence of BD-J/AACS/BD+ and the original CLI
inspection are source-acquisition context; that CLI does not replace the
designated Jellyfin Native reader in consumer comparisons. The original
CC-BY-3.0 film and credits remain unchanged; no encoder, muxer or media generator
creates any input.

The first Linux component run acquired the entire original and completed both
Native observations, then exposed an actual Node mapping difference: AC-3's
standard ffprobe codec_tag_string appeared as CodecTag, while Native returned
null. The designated MediaStreamInfo.cs maps the literal codec_tag_string?
JSON property, including its question mark. Production normalization now uses
that exact mapped input for stream and attachment tags. The complete probe
comparison retains CodecTag; no field is dropped or substituted in the fixture.
