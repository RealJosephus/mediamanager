# Owned mixed library exchange

This input declares one five-library topology. An untyped library contains a
TV Series and Season, Episodes, a Movie with two versions and two parts per
version, an owned Trailer and theme Audio, and a STRM shortcut. A typed Movies
library supplies a second complete version/part/Trailer/theme family. Separate
Music, Books and homevideos-with-Photos libraries share the same actual scan and
exchange. The source assets remain the existing MKV, original CC0 IETF CELLAR
FLAC, EPUB and JPEG. Their byte counts and digests are frozen in `input.json`.
Every physical media file is a byte copy. The fixture creates no audio/video
payload, edits no media tags and remuxes no container. Its declared NFO, STRM
and unknown sibling text are ordinary frozen filesystem inputs.

The consumer saves the same-run Native empty SQLite and complete instance before
installing the initial media. The actual Native server scans that frozen media
at its final physical paths and records complete rows, native Data, relationships
and HTTP consumers. Its stopped instance is retained separately; the saved empty
instance is copied back, its complete configuration bytes and full SQLite values
are checked, and Node uses the original unscanned empty PostgreSQL import.
The baseline's generated metadata and cache do not seed Node.

The untyped alternate's coercion to Movie loses its physical Parent. Its
AdditionalParts path remains declared, but the actual Native owned-refresh
boundary does not persist or expose that alternate's second part. The baseline
and Node both retain this row/API negative branch. The typed Movies family
independently requires actual owned rows and public AdditionalParts delivery for
every version's second part. Source files and complete actual results remain
evidence in both branches; no missing row is given a fabricated item identity.
Raw full graph prefixes are captured before topology assertions.

Owned-extra expectations come from the actual Native baseline's complete
Path/OwnerId/ParentId/PrimaryVersionId/ExtraType relationships, rather than an
input-supplied owner. Native repeats its scan and HTTP consumers before Node
starts; its ownership must remain exactly stable. In the observed untyped
branch, the generic Video part retains a physical Parent and refreshes the
directory's extras after its primary, taking their actual ownership. The primary's
empty LocalTrailers and ThemeMedia routes and the actual part's positive routes
are all consumed. Typed parts lose that Parent on coercion, leaving their
primary's positive owned-media routes. Node's first scan, cold reads, Native
continuation and the pre-deletion fresh PostgreSQL import must match the exact
baseline relationships; a different owner is a failure. Full original rows, native Data
bytes and ordered item relations are preserved before each graph assertion.

The Audio edit uses the controller's actual `ArtistItems` and `AlbumArtists`
NameGuidPair arrays. Its readback checks the complete names and the already
bound real artist identity, plus the separate `Artists` names, Album and
Overview. A string-array album-artist request is invalid and is not used as
a successful metadata edit.

Node scans, edits metadata and user state,
deletes a Book and Audio, and opens a new production runtime and PostgreSQL
connection. A complete SQLite export retains all business values, EF history,
sequence state and relationships. The actual Native server first consumes the
Node-created graph, then scans the declared additions. A fresh PostgreSQL
import and production Node runtime consume that complete version/part/owned
graph before its deletion. The actual Native server resumes its own stopped
SQLite instance, edits the Episode and deletes the two declared primary Movies.
A second fresh PostgreSQL import and production Node runtime must consume the
returned graph, unknown provider keys, user state, relationships and actual
media bytes. Every transfer boundary compares all native business tables,
including values outside the explicitly observed media items.

Deleting a primary does not declare its entire physical family deleted.
Native `LibraryManager.DeleteItem` can promote an existing alternate, and the
following actual scan can resolve surviving media to another type or identity.
`Video.GetDeletePaths` also distinguishes a containing-directory deletion from
a mixed-folder item's own path and metadata. Immediately after the two real
DELETE responses and scan, the consumer stops Native and retains its complete
31-table state, all BaseItems and ordered relationships, and each declared
source file's actual presence and unchanged bytes. This happens before any
post-deletion HTTP assertion. No file is manually removed to force a result.

Only this stopped Native state defines the new family phase. Each actual row
under the two physical family roots supplies its own Id, Type, Path, ParentId,
OwnerId, PrimaryVersionId, ExtraType, AdditionalParts and version arrays; neither
Node's result nor the initial family's static owner is used to choose it.
The same Native SQLite instance is reopened for cold complete DTO, parts,
trailers, theme and remaining-media reads. Old identities absent from that
SQLite, including the two deleted primaries, must return 404; surviving old
identities must still return their exact row's 200 response. Newly resolved
identities are bound independently to their original Native row and HTTP
response. Fresh PostgreSQL must reproduce the complete returned database,
these exact phase relationships and the final full DTO/media observations.

Native `MediaInfoHelper` enables playback probing; `MediaSourceManager` forces
a full metadata refresh for STRM playback. Each complete media observation
therefore retains its original pre-playback DTO and every media response, then
an independent DTO-only HTTP pass reads the final item, AdditionalParts and
owned-media DTO values used at the transfer
boundary. This pass does not request PlaybackInfo or static playback again.
Its full DTOs, fresh designated source bindings and the stopped original
SQLite rows remain in the report. Fresh PostgreSQL compares all 31 tables
unchanged and its first full DTOs against this actual final readback, including
the exact DateCreated and Etag; no date flooring or field omission is allowed.
Declared version membership is checked before primary deletion; after deletion
the stopped Native phase supplies the exact membership. Complete raw
array and relationship order remains in the snapshots and is compared exactly
through Native-to-PostgreSQL exchange and real HTTP consumers.

The shared state helpers are direct imports from
`tests/helpers/library-exchange-state.js`. The shared owned proxy retains the
existing Native controller's 5244 port contract and admits declared original
files only. The STRM source uses the explicitly declared loopback alias; it is
not an Internet media dependency. Actual source paths, HTTP request/response
bytes, pixel observations, process ownership and cleanup remain evidence.
Complete HTTP binary bodies are retained once per SHA in explicitly referenced
`http-body-<sha>.json` observations; every request still retains its own status,
headers, length, hash, phase and actual item identity. Content equality does not
discard a response or substitute a canned server reply. Photo previews request
lossless PNG and compare the complete decoded sRGB RGBA pixels; each distinct
wire encoding remains in the body observations. Complete item DTO comparisons
only canonicalize the declared date fields to full UTC 100 ns strings.
Diagnostic names, stacks, log absence and log counts are not business gates.

This fixture covers the declared five-library joint scan, metadata/user edits,
deletion, cold PostgreSQL, complete SQLite export, actual Native continuation
and final fresh PostgreSQL consumption. A post-deletion Native row can remain
publicly readable after its source file is gone: its exact stored graph and
cold DTO are preserved separately from the recorded physical absence. Missing
sources are never claimed as successful media-byte delivery.
The scope does not include real DVD/Blu-ray media or indices, production-scale input,
arbitrary plugin entities, client presentation or release acceptance. The
current complete-library verifier supports concrete filesystem Audio/Video;
its unchanged scope cannot certify this graph's Books, Photos, STRM or discs.
