# Native identity inputs

This binding selects newly recorded Artist and Studio identity evidence from
the designated Jellyfin workspace. The native runtime was built from the
captured dirty source, and its stopped source database was initialized through
actual native APIs. The historical missing evidence paths are not replaced.

Set `MEDIAMANAGER_IDENTITY_INPUT_ROOT` to
`D:/mediamanager-validation/20261011/identity-results/restoration-v1`.
The second independent repetition is in `restoration-v2`. Both directories,
the eleven exact preparation inputs, source database, runtime and SDK directory,
and two independent repeat audits are hash-bound by `binding.json`.

Each repetition contains fourteen native modes and ninety complete HTTP
responses: simultaneous same-name requests, two-way and eight-way path
collisions in both request orders, followups, and Unicode SortName creation.
Native identities come from actual native creation and SQLite deltas. The
recorder does not import the candidate identity implementation. Both collision
winners must occur in the declared native runs. All original BaseItems cells
and all seventy-two columns of new stopped identity rows are independently
verified; only the observed native creation clock can vary between repetitions.

The original executable, preparation, artifact, invocation, state, collision,
shutdown and candidate assertions remain active. The new namespace preserves
the existing native-instance, query and historical recording boundaries.
Output cannot overlap either the source input root or its parent.

These recordings do not prove native PID sealing, per-request all-table read
gates, complete build/tool/OS influence closure, full scanning, real client
interaction, or release acceptance. The audits retain those explicit limits.
