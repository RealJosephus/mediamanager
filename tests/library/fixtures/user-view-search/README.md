# Actual UserView search controller contract

The fixture keeps all 18 real frozen-server HTTP records, input constructors,
complete twelve-table item/UserData state, four filesystem domains, foreign-key
checks, raw source and process bindings. Every endpoint and the before/read/stop
windows was checked exactly equal before one full state was retained. Users,
policies, authentication/token/password tables and setup responses are outside
the native recorded state and are not copied. No response field is removed.

`NativeRecorder.mjs` is the exact executed recorder source, pinned by hash; copy
it to a new three-level ignored evidence directory before executing it with a
new output directory, port and this input file. `project-native.mjs` takes that
parent evidence directory after runtime/source and process audits. The fixture
pins 230 copied runtime leaves and eleven native source files. Runtime copies
were made after execution; the main executable also equals its pre-run hash.
The independent server used port 18243 and exited with code 0; its port and PIDs
were reclaimed. Tests need only tracked fixtures and installed dependencies.

Three explicit persisted UserViews (movielatest, moviemovies, moviecollection)
each have real Movie/Audio children. A provider hit bypasses their builder,
preserves Audio, and gives total 3 with request limit 2; explicit caller IDs are
unioned to give total 4. This holds for both users and API keys. No hit still
enters the builder: user responses are empty and the three API key controls
retain the actual 500 response. The native server executes real SQLite, search,
controller, entity and DTO methods. This proves these eighteen boundaries;
external providers, host cancellation and other view types remain outside it.
