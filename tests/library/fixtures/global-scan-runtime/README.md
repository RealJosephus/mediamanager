# Same-platform ordinary global scan

This fixture executes the eighteen ordinary-directory scenarios against the
designated Jellyfin source build supplied by the current Actions run. The input
is copied without changes from the recorded global-scan fixture. Its original
recording, historical provenance and replay test remain separate and unchanged.
The native host preserves the same real LibraryManager discovery, native folder
scheduler, metadata services, SQLite persistence, named forwarding IO/save
faults and cancellation boundaries. The two post-task bodies and directory
monitor are explicit controls; this fixture does not prove their real combined
operation or admit the complete product scan.

Each native scenario records its own physical roots, execution clock window,
raw SQL, event trace and released resources. Candidate media identities use
those actual same-platform paths through an isolated memory storage adapter;
candidate instance state lives in a different fresh directory. Comparisons
retain all 72 BaseItems columns, all captured relationship tables, fault
occurrences, cancellation outcomes and post-task/monitor commit prefixes. The
provider's early raw progress remains separate from scheduled scan progress.
Raw native output and candidate SQL/trace receipts are retained in the Actions
artifact. A successful comparison has its own receipt; failed runs retain their
actual observations without rewriting the old expected data.

Both cold-restart inputs also invoke the actual BaseItemRepository reader on
their own new SQLite aggregate row. The original nested container, an added
Folder IsRoot property and a wrong-shaped readonly container are separately
read and serialized. Candidate cold reattachment and SQLite export retargeting
use that same-run reader result, preserve actual state placeholders, and verify
that projection does not mutate the PostgreSQL source. Windows media identities
retain Windows path semantics; POSIX native identities retain POSIX semantics.

The test builds only in an isolated output directory through recordOracle.
Native processes, the native source offer and build receipts, complete inputs,
candidate identity and PostgreSQL cleanup are audited by the same Actions run.
