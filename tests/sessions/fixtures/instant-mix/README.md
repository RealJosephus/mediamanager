# InstantMix audio inheritance and view dispatch

The oracle executes the designated `MusicManager.GetInstantMixFromItem` and
actual `UserView.GetRecursiveChildren` / `UserViewBuilder` methods. Entity,
repository, genre, TV Next Up, configuration and user-data dependencies are
controlled. It records 66 cases, query flags, call order, selected identifiers
and exception diagnostics. No native database, HTTP listener or host starts.

`provenance.json` binds the exact oracle/project/shared properties, loaded
assemblies, runtime, raw recording and eight designated source files. The
source files matched the frozen build copy when the recording ran. The complete
reference build input closure remains unverified.

The candidate runs real PostgreSQL selection for all 66 cases. Comparisons protect
returned membership, source-first audio/audio-book order, empty results, failure
status and the original genre lookup order, including an injected per-name fault
and a successful lookup prefix before a later view cast failure. Candidate
lookups execute the actual directory/entity/Added creation service. Random order
within the mix and CLR exception labels are diagnostic. Native genre lookup is
controlled in this recording; its creation lifecycle is established separately
by `tests/library/fixtures/music-genre-creation`. Native InstantMix HTTP and the
concrete genre-ID repository are recorded separately in
`tests/http/fixtures/instant-mix`. A real native Next Up repository and Web clients
remain outside this recorder's scope.
