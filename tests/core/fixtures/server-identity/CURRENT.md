# Current server identity consumers

The current profile retains every original neutral identity input byte. Two
independent executions of the designated Native `DeviceId` implementation read,
generate, cache, persist and reopen identities through actual files. Node runs
the same scenarios, including encoding, invalid values, directories, read-only
files and a current Native file-sharing helper. Sharing receipts include the
requested and received path and mode, explicit ready/inspect/release messages,
process exit, and actual Native and Node read/write access while the holder is
alive. The Native capture records its same-process access separately.

Generated IDs retain their public N format, persistence, cached value and reopened
identity relationships. Node reads the actual Native-generated file, and Native
reads every readable Node file after generation, repair and lock release. Existing
identity text and unchanged file bytes remain exact. Errors and access traces are
diagnostic; the assertions concern the resulting identity and file state. The
runtime identity test separately checks actual PostgreSQL binding, public DTOs,
restart, complete state restoration and Native reads of restored, fresh and
repaired files.

The original input, observation, provenance and required-input manifest remain
unchanged as historical evidence. Current execution builds from the tracked
project and records current source, runtime and output identities on all three
GitHub Actions platforms.
