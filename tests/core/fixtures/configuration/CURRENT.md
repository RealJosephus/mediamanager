# Current configuration file consumers

The current profile retains every original neutral XML input. The workflow's
designated Native serializer, configuration helper and plugin configuration
loader execute twice against independent files. Node compares complete public
configuration values, accepted or rejected reads, file recovery and reopening.
All seven configuration roots retain their full default values, with the actual
host processor count supplied for the documented cache default.

The file-sharing helper is built in the current run. Its receipts include the
requested and received path and sharing mode, explicit ready/inspect/release
messages, actual Native and Node read/write access while the holder is alive,
and process exit. Native same-process access is recorded independently. Every
held input retains an independent accessible Native control and a Native read of
the original XML before the lock. The admissions recorded before each operation
determine whether the complete original value can be loaded, recovery requires
defaults, and a required write succeeds or is refused. Refusal must leave the
original bytes unchanged; an admitted write must reopen with the complete value
read from the independent Native control's actual serialized file. The initial
loaded value and the value read after serialization are recorded separately.
Native helper exclusive writes and plugin shared writes use their own measured
access. Both runtimes retain their actual held-file results.

Node reads each actual Native file after lock release. The actual Native
serializer reads every readable Node file in a fresh process, with input, output,
assembly and process receipts. The runtime scenarios retain UTF-16 and UTF-32 in
both byte orders, real PostgreSQL state, startup changes, cold restart and Native
configuration continuation, followed by Node reading the continued values.

Original source, input, observation and provenance bytes remain historical
evidence. Native type descriptors and exception details are diagnostics; public
values, real failure presence, file outcomes and bidirectional reads determine
compatibility. All execution occurs on Windows, Linux and macOS in GitHub Actions.
