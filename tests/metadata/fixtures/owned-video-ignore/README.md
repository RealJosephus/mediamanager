# Native owned-video-ignore

These 24 cases execute actual frozen ordinary video resolution with both
CoreResolutionIgnoreRule and DotIgnoreIgnoreRule registered. The library cases
run ResolveAlternateVersion/UpdateItemAsync; owned cases run RefreshMetadata,
RefreshedOwnedItems, CreateItem and independent deletion. Rules cover empty,
comment, invalid, negation, ancestors, nearest nested files and UTF-16 encoding.
Typed lookup bypass, wrong-type deletion before ignored resolution, cancellation,
exact Int64 and the complete original row/Data/file/cache/event projections remain.

Providers do not perform a complete save/refresh. Resolver type, filename parsing,
collection/saver/media-source/external file dispatch and known ancestor namespace
are controls. Candidate media use Memory VFS only as a fixture backend; instance
state files and both databases are real. Ignore-only ancestor mapping does not
remap instance files into media. No complete resolver/scanner, MetadataService,
network/symlink/concurrent cache, migration or release acceptance is claimed.
