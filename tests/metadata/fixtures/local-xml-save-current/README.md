# Current local XML save and readback

`local-xml-stream.test.js` runs twelve neutral input cases through the real Node local XML saver and the same-run designated Native `BaseXmlSaver`, `BoxSetXmlSaver`, `PlaylistXmlSaver`, `BoxSetXmlParser` and `PlaylistXmlParser`. A single oracle build performs two independent saves into new private directories and reads every original Node output file. Repository People/member inputs are explicit controlled dependencies; writers, parsers, filesystems and the Native save-manager continuation execute their actual implementations.

The cases cover existing/absent destination replacement, People/member lookup failures, invalid XML characters, successful metadata, null/duplicate/escaped paths in order, a Playlist directory whose name has an extension, a physical playlist file, 4097 prepared members, a failed frame uploaded once with declared conditional/atomic options, and continuation to another saver after a failure. Public save results, file replacement, reader success/failure, assigned values before failure, member order, owner/shares and save-manager monitor completion are required. The remote upload sink is controlled; this does not establish behavior of any external storage service.

Actual Native and Node XML bytes, digests, reader results and original error diagnostics remain in the output. Comparisons use the actual Native reader on each file, allowing equivalent XML formatting. Failure prefixes are real closed files and retain every value the consumer can read before failure. No old recording is used to generate either side. Source bindings and loaded application assemblies must match the same-run Native build receipt; compilation/run receipts and raw output are retained.

Historical `fixtures/local-xml-save-prefix/{native.json,provenance.json,Program.cs,Oracle.csproj,README.md}` remain unchanged. The former standalone assembly-seal test is preserved as `tests/metadata/local-xml-prefix-seal.history.js`, outside automatic test discovery. Its missing original Oracle binary is still missing; this current consumer evidence does not repair or reinterpret that historical seal.

Select `tests/metadata/local-xml-stream.test.js` in GitHub Actions, with `native_reference=true`, `native_instance=false`, `native_sqlite=false`. The declared services are `dotnet` and `jellyfinDll`; no PostgreSQL, supplied SQLite database or running Native instance is needed. This is component evidence, not complete-library, instance migration or release acceptance.
