# Generated splashscreen images

This fixture records 23 actual SkiaEncoder/SplashscreenBuilder cases, four actual perspective transforms, and ten actual SkiaHelper observations. The producer declares inputs independently and uses the designated build-copy assemblies. `files.json` binds all 55 copied raster/input files to their original bytes; the directory marker retains the native directory-input control in a checkout. JSON/C#/project bytes are unmodified.

Cases include empty/one-sided inputs retaining an old file, PNG/JPEG/WebP/content-based decoding, alpha with a renamed extension, enlargement and mipmap reduction, invalid/missing/directory inputs, a single-frame GIF rejected by the native frame check, SVG rejection, zero-width tiles, missing output directories, directory/read-only outputs, and repeated random mixed composition. Helper observations cover cycling, missing/invalid images, directories, and actual decoder pixel hashes. The repeated mixed native calls produce different pixel hashes; both original files are retained independently.

Generated splashscreens use a consumer-specific raster comparison. The actual web source displays `/Branding/Splashscreen` as a backdrop; the controller delivers an image without a fixed pixel-hash contract. `files.json` records these source identities and explicitly marks this as source inspection. Production branding routes and full web-client acceptance are separate unfinished release work.

All decoder input pixels are exact. The complete 5760x2160 wall must match the native six-row composition with at most one RGB code value of cubic quantization, with alpha exact. Reduction uses the existing linear mipmap implementation. The independent coordinate image encodes every wall pixel index into RGB; the actual transform reveals every selected source cell. Tests solve the forward projection equations independently and allow a cell-boundary choice only within 16 IEEE single unit roundoffs in source coordinates. Two-pixel displacement counterexamples must fail. Native and candidate raster colors must exactly equal their respective selected wall pixels at every target pixel. Solid transforms, dimensions, opacity, retained files, failure prefixes, and resource effects remain exact.

The new generated-splashscreen comparison accepts platform floating-point and quantization differences under the project's R23 rule; it does not change ordinary processed PNG/WebP tests. Pixel hashes, byte hashes, sizes, quantized channels, and boundary choices remain diagnostics. This avoids reproducing CPU reciprocal instructions in production. The generator uses ordinary Node projection and existing static canvas/PNG libraries; it reads media through VFS and writes only the instance's `data/splashscreen.png`.

Tests cover actual runtime/PG/VFS wiring, rejection of an unmapped readable host file, stream closure, failed reads preserving an old output, serial generation admission, and shutdown cancellation of active and queued work. The fixture does not establish a full native host, a complete build-input closure, audiovisual transcoding, or final release acceptance.
