# Public original live streams

The HTTP test starts a private copy of the current designated native instance,
disables scheduled triggers through its real API, installs a local M3U tuner
through the real controller, and obtains its actual Guide-created channel.
Both timer documents are explicitly empty before the first native startup.
The stopped database is transferred to a fresh PostgreSQL schema before either
observation sequence. Node starts through the production entry point against
that transferred state and the same mapped playlist bytes.

The M3U configuration sets `AllowStreamSharing=false`. Native `LiveStream.Open`
therefore reserves/describes the original HTTP source; its real ffprobe process
reads the supplied finite handwritten PCM WAV. Native `SharedHttpStream.Open`,
file copy, recording, packet copy and encoding never execute. The default
service can still retain the same reservation by `OriginalStreamId`; blank
original IDs instead create fresh inputs with the same public source ID.

The full public responses, status/content type, source ID, OpenToken,
LiveStreamId and cache files are retained. Random top-level PlaySessionId values
are validated before mapping; trace IDs are validated before mapping. The
native response's SupportsTranscoding is explicitly projected to false for R6;
all remaining source fields participate in comparison. Runtime/cache paths are
the same controlled identities on both sides. Actual native MediaInfo readers
consume both hosts' cache bytes and Node consumes the native bytes as well.

This fixture does not claim a native retained byte transport or actual
SharedHttpStream playback. A separate Node real-ffprobe/private-bridge test and
public registry tests cover bounded byte readers and close ownership; native
controller retained-stream component evidence has its own boundary. Component,
real HTTP and process evidence are not substituted for one another. All phase
and final release acceptance flags remain false.
