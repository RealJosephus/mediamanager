# Current HTTP subtitle components

This recorder supplies real HTTP subtitle identities. `MediaStream.Path` is the
original `http://127.0.0.1:5244` URL, including its query and percent spelling.
The media source may independently have File or HTTP protocol. The fixture does
not relabel a File identity sent through `LocalMediaProxy` as HTTP evidence.

The raw component calls the actual designated `SubtitleController.GetSubtitle`
with an empty format, its actual `FileStreamResponseHelpers` branch and the real
ASP.NET `ActionResult` executor. Its component host provides the `/Stream` test
endpoint. HEAD separately passes through the designated `AddJellyfinApi`
registration and actual `SubtitleController` MVC method matcher at `Stream.srt`;
the capture distinguishes method routing from action/result execution and retains
the real Allow header. This does not certify general MVC binding, authentication
or full Native server coverage. Normal formatted operations also call the real Controller and execute
its returned `ActionResult`. Caller-token cancellation cases separately call the
actual public `ISubtitleEncoder`. Both use actual `ExceptionMiddleware` in
Production mode, with real filesystem,
path manager, configuration manager, media encoder, parser and HTTP clients.
Only item/source descriptors and the owned HTTP input/control are controlled.
Unused dependencies fail the recorder rather than establish a 500 baseline.

The named default source client follows the designated `Startup.cs` contract:
automatic decompression of all supported encodings, UTF-8 request-header encoding,
the actual Happy Eyeballs connect callback and the Native product/Accept headers.
The product metadata comes from the same-run designated assemblies. Source
receipts preserve the actual requests. This matters for gzip and unknown-length
streams: plain-body File observations do not certify these HTTP results.

`input.js` declares BOM SRT, ASS, `.smi`, `.sami` and the previously proved UTF-16LE
SAMI bytes. The matrix includes raw GET/HEAD, normal/suffix/unsatisfiable ranges,
If-Range match/mismatch, ignored ranges, 403 and 404 bodies, redirects, gzip and
chunked bodies. Formatted non-2xx and decoded text are consumed independently.
The original URL string also governs Native extension/charset selection; a query
can cause a parser-supported leaf name to enter real FFmpeg text fallback. The
recorder preserves that actual outcome rather than extracting a replacement URL
pathname or inventing a supported parser result.

An independent source host owns port 5244; the component result host uses its own
ephemeral port. `offline` actually stops the source host. `online` creates a new
host on the same source port. Each independent case begins with an available
source host. HTTP `.sami` cases record cold/warm/new encoder use, a nonempty cache
without metadata, preexisting metadata, changed upstream bytes, genuinely offline
source, zero-byte cache and its real retry. Native chooses its actual
`data/subtitles/<prefix>/<GUID-D>/<index>.srt` path; SRT and metadata remain exact.
No local source fingerprint is invented from ETag or Last-Modified.

Cancellation has separate observations. A raw controller response is read
through its real executor, then the HTTP client cancels while the upstream body
is held. Charset and FFmpeg cancellations use the actual public encoder caller
token, triggered only after the corresponding real source read; FFmpeg also
requires its actual child-spawn receipt. Native's full SubtitleController calls
the encoder with `CancellationToken.None`, so these formatted component token
observations are explicitly not a controller client-disconnect claim. Original
error bodies, partial data, process absence, source drain and final host closure
are retained. Emergency fixture killing fails the capture.

One independent `.sami` operation also invokes the real formatted Controller,
waits for actual FFmpeg spawn and its held input read, disconnects the HTTP
client and waits for the server's actual `RequestAborted`. Only then does it
release the source gate and wait for the real producer, result and child to end.
It records actual cache/meta and error outcomes without inventing a response or
assuming whether the producer commits or removes its cache. A cold Controller
request consumes the resulting state. The gate is also released during fixture
failure cleanup, so `CancellationToken.None` is never held indefinitely.

The small profile matrix calls the real public static
`StreamBuilder.GetSubtitleProfile` for external streams, External/Hls profiles,
DirectPlay/Transcode and exact/convertible format candidates. It records every
public profile value and uses a complete controlled support object that forbids
generation. It runs no transcoder and makes no PlaybackInfo or general stream
selection claim. A manually reachable writer does not prove an advertised
profile. No CLR object identity, private call count or PID equality is a gate.
TTML candidates and the focused `webvtt` to SRT cases are included in this static
profile matrix. Four embedded ASS/SSA External/Hls cases independently exercise
the same advertised conversion restriction. The PostgreSQL HLS consumer retains
an explicit authenticated ASS-to-WebVTT request without advertising it from an
unsupported playback profile. They use the real advertised-conversion rule; they add no HTTP
process scenario and do not infer advertising support from a manually reachable
writer.

The copied apphost admits only version/probing of declared subtitle sources and
the exact `-c:s srt` text operation into a declared Native cache. Audio/video
encoding, rendering, OCR, filters, hardware and arbitrary outputs are rejected.
The original File recorder and its execution boundary are unchanged.

The caller holds `native-media-5244` once around
`captureCurrentHttpSubtitles({ output, inputFile, signal })` and its Node
consumers. `inputFile` may be omitted to create `subtitleHttpInput()`; the return
value is `{ output, input, native, repeat, report }`, where `input` is the parsed
scenario object. Each Native recording gets independent source/config/cache and
process roots. Full source/tool/build seals, original input bytes, source request
and response bytes, public status/headers/body, cache/meta bytes, errors, traces
and stdout/stderr files remain available in both originals.

Repeat comparisons concern functional selected headers and complete bodies,
source identity, persistent bytes and actual lifecycle outcomes. Date/Server
headers, absolute output roots, diagnostic errors, charset confidence, PIDs and
request counts are retained without comparison. Only GitHub Actions executes
builds, checks and this recorder. These finite component results cannot certify
full MVC binding, full authentication, a complete library or release acceptance.

The current Node consumer compares generated SRT line layouts only when the
declared original SAMI asset has `.smi` format, the complete unchanged source URL
still selects `smi`, and the actual formatted request selects SRT. It reuses the
proved SRT reader projection: only CRLF, CR and LF separators map to lines;
numbering, timestamps, text, blank lines and the final line stay exact. Both
original responses remain in the evidence. Raw and same-format responses, URI
query variants that select text fallback, all persistent SRT/cache/meta assets
and both directions of cold cache handoff continue to compare complete bytes.
