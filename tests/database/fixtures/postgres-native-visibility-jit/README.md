These six tests use real PostgreSQL operation sessions and inspect `current_setting('jit')` and `pg_backend_pid()`. They cover original on/off values, bounds, root-to-owned-session pinning, expired sessions, complete same-client lease ordering, transaction-local success and rollback after a real division-by-zero error, caller cancellation after admitted SQL, and an admitted query held across pool close.

The restoration fault changes only that test session's restore dispatch to a real `current_setting` request for a nonexistent setting. PostgreSQL returns `42704`; the helper must aggregate that actual failure, preserve any primary callback error, quarantine the physical client, reject a queued lease, and obtain a different backend with its original default on the next checkout. No server or pool-wide PostgreSQL defaults are changed.

The cancellation case executes real SQL with the caller's signal and then aborts its admitted callback before completion. It proves that cleanup SQL receives no caller signal and restores the setting; it does not claim node-postgres network cancellation of an in-flight statement. All controlled gates are released in `finally`, and each test drops its isolated schemas and closes its pool before writing its result. No native media or application playback runs here. Full-suite, phase and release acceptance remain false.
