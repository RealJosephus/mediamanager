# Current warm deletion HTTP consumers

`current-profile.json` binds all 16 existing warm/cold Audio, Video, Folder and
MusicArtist single/batch scenarios to the current driver, project and shared
build properties. The same Actions run records the supplied designated Native
MVC LibraryController, AddJellyfinApi, binders, formatters and exception
middleware with real LibraryManager/EF SQLite/files/cache/events.

The Node consumer uses the Native pre-operation rows in isolated PostgreSQL/VFS
state, deletes the Playlist closure, then sends the actual DELETE request to
the Node HTTP application. It compares status, content type, response body,
all persistent values, links, file hashes, lookups and ordered side effects.
Only the nonempty opaque request trace uses the current shared response projection
in `tests/http/deletion-response-projection.js`; it verifies the parsed body and
preserves bytes outside that top-level value. The historical format-specific
normalizers remain sealed and are not used by current consumers.
The driver's own state root and filesystem separators relocate to `$STATE`;
Data is parsed for relocation, not claimed as raw SQL TEXT byte evidence.

Exact consumed input bytes, raw Native response/recording, SQLite state, source
copies, build logs and process receipts remain in the isolated validation
output. The historical input, driver, project, README, recording, provenance
and absolute evidence references remain intact.

The API-key principal/default policy, application paths, collection-folder
resolver and external provider are explicit controls. Native authentication
handlers, user cleanup, complete metadata/scanner coverage, clients, instance
exchange and release acceptance remain outside this fixture.
