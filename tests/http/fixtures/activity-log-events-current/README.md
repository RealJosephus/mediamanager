# Actual activity-producing HTTP and WS consumers

This Actions-only fixture starts the designated same-run Native server in a
private clone. Native HTTP prepares an ordinary observer, an API key and an empty
library. A finite Book control and real source bytes are inserted into the
clone's genuine migrated schema after shutdown. A complete stopped SQLite input
is frozen before the business matrix; fresh PostgreSQL imports that same input
before the production Node entry point repeats the actions. The original stopped
instance and designated source build remain immutable.

The 28 declared actions exercise `UserCreated`, `UserDeleted`,
`UserPasswordChanged`, `UserLockedOut`, `AuthenticationSucceeded`,
`AuthenticationFailed` and the common `UserDownloadingContent` writer. They use
real user creation, password changes, login, policy and deletion endpoints, and
a real local Download file served through the designated proxy on port 5244.

For Node, the configured VFS resolves the declared local mount to its plugin
adapter facade. The facade exposes the actual installed adapter's prototype;
the plugin scope dynamically invokes that owner's `openRead` method. The fixture
observes this real method entry, reads the committed PostgreSQL prefix only for
the declared Book's actual root and resolved adapter path, and invokes the
original method with its original receiver and arguments. It supplies no
replacement bytes and restores the original prototype descriptor before runtime
shutdown. A restoration error does not skip shutdown. Instance and metadata
reads continue through their original storage operation.

Anonymous/ordinary creation, unknown or empty usernames, disabled users, device
restrictions and the active-session limit retain their actual public refusals
and committed activity prefixes. Existing-user wrong passwords exercise the
failed-authentication logger; the threshold attempt exercises the lockout logger
before that failure. Unknown users are not assumed to publish failed events.

New user IDs and access tokens are independently generated by each real server.
Each runtime binds the actual create response to its own stored user row, event
user IDs and subsequent HTTP operations. Successful authentication tokens are
used against the real `/Users/Me` endpoint. Only these declared identity aliases
are substituted in comparisons; original response text, activity rows and the
actual identity maps remain in the filtered report. Password/hash/token values
are not compared as deterministic outputs. New activity IDs remain valid, and
actual generated times must belong to the business request window.

Seven actions inject a real database `BEFORE INSERT` trigger for the scoped
activity types. Native injection first passes the normal complete schema
preflight and keeps that same owned SQLite handle until the trigger is removed.
PostgreSQL uses an actual trigger/function in its owned schema. The public
operation must still commit its user, password, authenticated token, login
attempt, disabled state, deletion or actual file response. Every trigger is
removed before its owner closes. Failure is observed at the real activity write;
no logger, controller, event manager or database service is mocked.

Admin, API-key and ordinary WebSocket clients connect to each actual host.
`ActivityLogEntryStart` is synchronized by the real keepalive protocol. The
designated listener queues forced entry-created notifications through an
unbounded channel and returns `Data=[]`; it does not poll from the supplied
delay/period values. Actual committed scoped rows must become visible to the
admin and API-key consumers at notification receipt. An ordinary observer
cannot subscribe. All original frames, empty payloads, message IDs, readbacks
and socket shutdown observations remain available. Notifications from other
real Native producers and asynchronous delivery are retained without imposing
a notification-count equality or a private queue representation.

The complete before/after activity rows include out-of-scope entries. Native
SessionStarted/Ended, playback, task and plugin producers are not silently added
to the completed scope. Comparisons cover the declared event fields and order,
user aliases, severity, row version, null/empty values, request-time membership,
public HTTP results and persisted user state. CLR classes, stack traces and
diagnostic log counts do not control acceptance.
Each step receives its `completed` report marker only after its existing HTTP,
database and WebSocket assertions finish. A partial step retains its raw and
functional snapshots; provenance counts only completed steps.

Only filtered reports, source bindings and process logs are published after
Native, Node, WebSockets, source server and PostgreSQL owners close. Leases own
the Native fixed ports, discovery and download proxy throughout cleanup. A
dispatched test or a partly recorded Native matrix is not a passing result.
This bounded consumer does not establish complete activity-producer coverage,
media scanning/decoding, full-instance migration, production scale or release
acceptance.
