# Quick Connect oracle

`input.json` drives 74 HTTP observations through the designated Jellyfin
QuickConnectManager, QuickConnectController, UserController, MVC model binding,
exception middleware and default authorization handler. The authentication
principal, authorization information, user/network service and session manager
are controlled. The session seam returns a fixed AuthenticationResult; it does
not prove real device persistence or the full authentication DTO.

`Direct.cs` additionally executes the actual SessionManager.AuthenticateDirect
for nine cases. User/device persistence and events are controlled; the invalid
username guard calls the actual UserManager. These observations cover absent
users, password-provider bypass, device/session restrictions, token rotation,
independent delete/insert failures and unchanged login counters. Native database
integration and the Web clients remain separate acceptance work.

`native.json` preserves the original recording bytes. `provenance.json` binds the
neutral inputs, source files, matching isolated source copy, loaded assemblies,
build/run and independent repeat. It does not establish complete historical
build input closure. Secrets and codes are independently generated by each
producer, validated, then consistently bound across responses and request
state. Generated dates must fall within the actual creation/authorization
window; expiration probes use explicitly controlled dates. Only those runtime
identities and HTTP trace IDs are projected for comparisons.

Record into a new absolute directory with the configured isolated DLL/runtime:

```text
node tools/compat/record-quick-connect.js NEW_ABSOLUTE_EVIDENCE_DIRECTORY
```

The candidate HTTP tests compare all 74 status/header/body/call outcomes. Separate real
PostgreSQL/runtime tests exercise actual users, token/session persistence,
authorization, restart, failure prefixes and shutdown. CLR exception type names
and controlled helper internals are retained as diagnostics.
