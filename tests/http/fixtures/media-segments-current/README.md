# Current retained media segment HTTP reader

The differential runs the designated build's actual MVC, authorization policy,
MediaSegmentsController, MediaSegmentManager and EF SQLite query against a
private copy of its same-run stopped database. Principal creation, library
lookup/visibility, library options and installed provider names are controlled.
All provider execution methods throw if invoked; no analysis or generation runs.
Source bindings and the full original responses are retained in the report.

The same complete SQLite database is imported to real PostgreSQL. Node uses its
actual application router, authentication authorization, media-segment service
and streamed HTTP response; the same explicit library/principal/provider
boundaries remain controlled. The matrix covers missing/hidden/empty identities,
authorization before model errors, ordinary MVC enum collections (including
comma combinations and indexes), disabled/uninstalled providers, JSON profiles,
unknown persisted enum values and signed full-range Int64 ticks. Equal start
ticks deliberately have a different order from the Guid key order. Results
cross 128 rows; SQL owns filtering, count and order and supplies bounded pages.

After the read matrix, real PostgreSQL delete/reinsert/add/delete mutations are
exported with all business tables and original migration history. The actual
Native manager rereads this export without reseeding, then a fresh PG import
checks the full database digest and media-segment insertion order. This is a
retained-reader exchange, not a complete production-scale instance acceptance.

The unextended production Node host currently registers no segment-provider
identities, matching the designated core host without provider plugins: its GET
returns an empty result even when uninstalled-provider rows remain. The
nonempty controlled provider matrix does not establish a production plugin
registration contract or authorize generation. Existing HasMediaSegments DTO
behavior still observes persisted rows independently of that provider filter.

The separate Node/PG failure scenario executes a real undefined-relation SQL
failure after cursor declaration, observes the actual discarded backend gone,
then repeats the same HTTP request successfully. Consumer plus real cursor-close
SQL failures preserve ordered causes and public error metadata, including a
literal false rejection and throwing metadata getters. These controlled Node
failure cases are not described as paired Native failure observations.
