# Saved Live TV timer HTTP consumers

`../../live-tv-timers-native.test.js` uses the current designated native build and its stopped controlled instance. No historical HTTP or WebSocket response is replayed. Source bindings name the actual controller, manager, timer managers, recording notifier, WebSocket serializer, event model, entity models and DTO models in the executing build manifest.

The native side has three real process lifetimes. The first receives empty `timers.json` and `seriestimers.json` before startup. A real user-view request discovers the configured global Live TV identity; the test waits for that exact row's non-MinValue `DateLastRefreshed` commit before collecting read-only snapshots. After empty-list/default/error requests and clean shutdown, the stopped private SQLite database receives controlled channel, program, Series, ancestor and image rows. Both timer documents are then populated before the second native process starts. The third lifetime later starts from the exact export of a closed Node runtime and continues cancellation. The native timer managers and startup behavior run unchanged. All timer dates are tied to the current run's real clock, strictly in the next one through six days, with full 100ns fractions; no timer is due during the test and the timer duration remains below the native scheduler's approximately 49-day limit.

Each primary Node stage creates a new PostgreSQL schema, copies the stopped private native media rows and relations with the same insertion order, and writes the same original timer bytes before its first `createRuntime`. An explicit absent-state assertion precedes runtime construction. Only the ordinary runtime `initializeLiveTvState` imports the timer documents; the harness never replaces or constructs the authoritative PostgreSQL timer state. This is real PostgreSQL/runtime/HTTP evidence, not a production entry or CLI import acceptance claim. Instance paths are rebased only for the controlled Node copy. Image rows point to the same actual private PNG asset on both sides, preserving the identity used by image cache tags; dimensions come from that PNG's header. The test covers image selection/tag/association fields and does not claim image endpoint pixels.

Read requests cover anonymous/invalid/ordinary/disabled-Live-TV/admin/API-key authorization; empty and nonempty timer/series collections; New, InProgress, Cancelled, Error, ConflictedOk and retained Completed state; active/scheduled/channel/series filters; native GUID query forms; ignored unbound paging/user/field selectors; stable name/numeric/priority ordering; string-detail identities and missing/invalid/whitespace paths; and Defaults with missing, malformed, wrong-type, missing-channel and foreign-service program inputs. Full HTTP status, content type, JSON or original non-JSON/empty body and order are compared. Only actual trace IDs and equivalent date spelling are projected; UTC presence and full ticks remain checked.

The populated lifetime also opens real authenticated WebSockets for an access-only user, a manager with access, a management-only user, a denied user, an administrator without explicit Live TV access and a userless API key on each server. DELETE requests first prove authentication, `LiveTvManagement`, whitespace binding, unknown identities and the exclusion of a Completed timer without changing any durable state. Accepted requests then repeat an already-cancelled timer through administrator and API-key credentials, delete an unlinked timer, cancel a linked timer in place, and cancel a series containing InProgress, Error, Completed and already-Cancelled children. Both explicit `LiveTvAccess` sessions must receive the same complete public WebSocket envelopes in source-child order; management-only, denied, administrator-without-access and API-key sessions must receive none. Every cancellation envelope must contain exactly `Data`, `MessageId` and `MessageType`, and one fresh `MessageId` must be shared across both eligible sessions for each broadcast. The random identifier remains per-runtime identity, while `MessageType` and the complete `Data` object are compared exactly, including native omission of null `ProgramId`.

After the Native mutation and clean shutdown, its exact resulting `timers.json` and `seriestimers.json` bytes initialize another absent-state, fresh-schema Node runtime before the independent primary Node mutation begins. That runtime must retain those input bytes, bind them as PostgreSQL authority and first return the same post-mutation HTTP collections and detail/not-found results as Native. PG2 then uses its management-authorized public HTTP route to delete the surviving, childless `series-zero-two`; PostgreSQL authority and its published file must reflect that Node-side change without changing copied business tables. Its normal clean shutdown exports the changed authoritative bytes. The fixture restores that Node export into the real Native instance, proves the Node deletion through Native public reads, cancels the surviving `series-two`, and shuts Native down cleanly. PG3, another absent-state PostgreSQL schema, imports the exact continued-Native output, verifies its file hashes and PostgreSQL source authority, and compares its public collection and detail/not-found reads with that Native lifetime. Reads, mutations, shutdown snapshots, listener release and schema cleanup are retained for both fresh schemas. This proves a real Native-to-Node-mutation-to-Native-mutation-to-Node continuation through ordinary file, startup, HTTP mutation and shutdown paths; broader state-package and production cutover acceptance remain covered by dedicated migration evidence.

The Native and independently-mutated Node HTTP readers are also compared for remaining and removed resources. Native SQLite business tables must stay unchanged. Both persisted timer documents are decoded to the typed consumer meaning affected by cancellation: entry order, external and series identities, status, manual flag and remaining series identities. JSON whitespace, property order and explicit default-valued members are not compared across the two writers because the native serializer reconstructs typed objects while Node preserves untouched source tokens; those non-functional representations are not an R23 gate. The Node PostgreSQL control state must instead bind the exact bytes and SHA-256 of both published Node files, and its indexed external identities/statuses must match those documents. This verifies public behavior, equivalent durable-state meaning and Node PostgreSQL/file authority without treating PostgreSQL index offsets or .NET serializer internals as product behavior.

Channel links, `ProgramInfo`, record status overrides, shared Series/program/channel image tags, daily/weekly patterns, constructor defaults and padding are exercised by these actual HTTP readers. The full before/after/closed database and document snapshots are retained per side. Read-only matrices must leave media/UserData/permission/preference/relationship tables, timer documents and the Node control-state string unchanged. Cancellations may change only the timer documents and Node control state; copied business tables remain unchanged. Final Node state is captured after HTTP/background owners close, immediately before the database owner closes.

After the populated read matrix, only the Node source documents change to empty bytes. Warm reads and a real runtime shutdown/reopen must still return the original PostgreSQL business state. This deliberately demonstrates ordinary read authority. It does not claim that a state package can be captured successfully from mismatched source files; the separate state-package contract rejects that mismatch.

Every actual HTTP and WebSocket observation, per-request Node runtime errors, original and mutated source bytes/SHA, SQL state, view commit row, private image identity and process/port/schema/input cleanup is retained through the credential-filtered private-output workflow. The zero-GUID Defaults request throws a domain error that the production middleware reports before returning 400; its exact error is checked separately from successful and binding responses, which must report none. Syntax, runner and HTTP/WebSocket execution occur only in three-platform GitHub Actions. This fixture covers DELETE cancellation but not the four POST create/update recorder boundaries; their shared controller/DTO binding and provider-dependent R6 terminal behavior remain covered by the dedicated mutation HTTP evidence. This fixture cancels inert saved state only and provides no tuner/listing/recording execution, complete clients, complete Live TV, production-scale or release acceptance evidence.
