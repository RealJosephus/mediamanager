# Native branding actions and file lifecycle

`input.json` is independent request, configuration, MIME and Base64 stream input. `Program.cs` hosts the loaded `BrandingController`, `ConfigurationController` and `ImageController` in isolated ASP.NET Core MVC with native API options, JSON conversion, client-error results and exception middleware. `ServerConfigurationManager`, `BrandingConfigurationFactory`, `MyXmlSerializer` and the upload's `CryptoStream` execute over real isolated files. Named configuration events and disk/live options are captured separately, including read-only failures and the configuration-before-file upload order.

Authentication identities and the elevation policy are controlled. Image processing records the actual options and returns the input file without rendering it; this fixture proves controller negotiation, headers and delivery, not image conversion. The candidate runtime tests separately execute PostgreSQL authentication, original PNG delivery, mapped VFS images, configuration restart recovery, active/queued upload shutdown and constructor rollback. Neither set proves complete native server authentication, full build input closure, both Web clients or all formats.

`transforms` runs the native Base64 reader over declared stream chunks. Complete blocks reject malformed padding and nonzero padding bits, incomplete tails are discarded, and earlier output survives a later rejected block. HTTP files and streams compare actual bytes; JSON compares lossless values, with only the runtime trace ID removed. State paths are mapped between the actual isolated roots. Image headers use the established limited projection. No image pixels or error messages are inferred from the candidate.

The 87 image MIME/extension pairs in `src/images/resources/image-mime-extensions.json` are factual observations from the loaded native `MimeTypes.ToExtension` lookup, including native overrides. No generated MimeTypes C# implementation is copied into production. The lookup in the source consumes the MimeTypes 2.5.2 package; its package metadata is Apache-2.0. Jellyfin controller/configuration sources remain GPL-2.0 and are bound in `provenance.json`.

To record, supply the isolated `MEDIAMANAGER_JELLYFIN_DLL` and matching `MEDIAMANAGER_DOTNET`, and invoke `tools/validation/oracle.js` with the project, a fresh output directory, a new state directory, this input file and the new native JSON destination. Keep original recording bytes and bind the source files, DLL/assembly identities, project, build and run before accepting a replacement recording.
