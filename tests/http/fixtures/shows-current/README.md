# Same-run Shows capture

This fixture retains every controlled input and native probe from the historical
`shows-api` oracle. It runs the actual supplied designated build twice in fresh
output directories, using currentNativeReference and recordOracle. The current
source manifest binds all 48 original controller/manager/provider/repository
source paths. The actual loaded managed assemblies and platform SQLite module
are rehashed for both independent executions. Historical recordings and seals
are unchanged; missing historical Oracle builds, logs or repeat captures are
not reconstructed or impersonated.

The supplied RID SQLite module is explicitly loaded and bound to the actual
SQLitePCL imports before database execution. Import resolution is a hard gate;
module bytes are rehashed even on macOS where Process.Modules omits that library.
The optional ChannelInfo assertion compares complete ordinary DTOs by identity
for local Similar requests, whose native contract uses a fresh Random order.
It preserves every DTO field and the complete count/paging envelope.

Two additional controller scenarios select SeasonUserData, RefreshState and
ExtraIds. These declared fields have no producer in the designated DtoService.
The PostgreSQL HTTP consumer compares complete responses with and without them
for Upcoming, NextUp, Episodes, Seasons and Similar; Episodes and Seasons also
compare the same-run controller's selected identities and paging envelope.
The concrete DTO no-op is covered by item-collections-current and dto-details.

The same four tests retain all original controller, binder, repository, provider,
cache, cancellation and PostgreSQL HTTP assertions. Only execution-clock cache
expiry and per-build assembly locations/Oracle identity are projected when
comparing the independent native captures; each raw identity remains bound in
its original receipt. Each cache also records the complete raw JSON. Before
normalizing execution-clock JSON and its variable byte length, the consumer
checks the actual UTF-8 length, complete property list, exact expiry ticks and
exact template reconstruction for each capture. Fractional-second trailing
zeros cannot create a false repeat difference; all other cache content and
the configured expiry-window assertions remain exact.

The native component uses actual EF SQLite with explicit
controlled entities and provider/lookup seams. It does not demonstrate actual
ASP.NET authorization filter execution, concrete DtoService internals, live
external services, production instance exchange or deterministic Random order.

All captures, builds and consumer tests run in Actions. No historical runtime
substitution, candidate-generated expected output or compatibility fallback is
used. Capture completion alone does not establish consumer or release acceptance.
