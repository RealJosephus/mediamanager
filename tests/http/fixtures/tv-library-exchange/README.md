# Ordinary TV scan and exchange

`tests/http/tv-library-exchange.test.js` supplies a new isolated library to the actual current Native HTTP server, then lets the production Node/PostgreSQL runtime create its business rows from real files. No TV item, relationship or probe result is inserted as an expected result.

1. Clone the same-run stopped Native instance; remove only its two documented synthetic preparation rows, disable scheduled triggers, create an empty `tvshows` library through the real API and stop it cleanly.
2. Import every table into a fresh PostgreSQL schema. Materialize one Series, physical Specials/Season 1, and three MKV Episodes in non-episode order, with independent nonempty local NFO input. The real registered Node scan resolves the hierarchy and probes audio/video. HTTP editing of Episode 1 writes its actual NFO.
3. Close and reopen both PostgreSQL and the production runtime. Compare public DTOs, physical parents, series/season IDs, source metadata, `Shows` ordering/counts/pagination, and declared source/NFO files. Export all 31 business tables and both EF tables; preserve history, insertion order and sequences.
4. Install that export in the stopped private Native clone. Its first actual API reads consume Node-created items. Change only the plot payload in the actual Node-written NFO, declaring a write time two minutes later to exceed Native's one-minute self-save tolerance, add Episode 3 from real media/NFO files, and execute the real Native scan. It must read the changed NFO and probe the added media. Native HTTP then edits Season 1 and writes NFO.
5. Stop Native, reimport its complete SQLite into another fresh PostgreSQL schema, and start a fresh production Node runtime. It must consume the added Episode, edited metadata, relationships and public order; all declared media and NFO bytes remain available.

The fixture generates a tiny FFV1/PCM MKV with the supplied real FFmpeg. That is input preparation. The actual Native workspace uses `127.0.0.1:5244/d/...` for local media, so the fixture must own that port and only serves four exact private business filenames, including actual Range requests and source digest checks. It fails on an occupied port and never reuses an existing service. Node uses its normal VFS probe bridge. Host ancestors map to a separate empty read-only directory for ignore lookup; the only writable library mapping is the private fixture root.

The JSON report and original Native logs are published with secrets filtered, along with hashes for input, media tools, requests, public results, persisted rows, complete-table snapshots and cleanup. The generated media input and each observed NFO retain their original bytes as base64 in the report. Stage flags derive from completed observations. Native input, runtime and source bindings are checked by `currentNativeReference.finish()`; both PostgreSQL schemas, owned servers and proxy must close before private evidence is removed.

Only GitHub Actions may execute this test. Select exactly `tests/http/tv-library-exchange.test.js`; supply same-run current Native source/build/instance, dotnet, FFmpeg/ffprobe and isolated PostgreSQL (`native_reference=true`, `native_instance=true`, `native_sqlite=false`). This is a scoped ordinary physical TV chain, not a full library/instance, all TV topologies, remote provider or production-scale acceptance. Required observations cover public behavior, persistent data, relationships/order and consumer-readable files.
