# Startup HTTP, user and configuration fixture

The recorder executes the designated workspace's `StartupController`, MVC binders, default and first-time authorization handlers, `UserManager`, EF SQLite, `ServerConfigurationManager` and `MyXmlSerializer`. Authentication principals, network classification and event consumers are controlled. Each scenario has a fresh database and native configuration directory.

The 82 scenarios contain 85 requests. They cover initial user creation and the two GET aliases, incomplete/completed setup authorization, required bodies, scalar string conversion, duplicate properties, malformed Unicode, remote-access settings, existing passwords, username comparison, user-save/rename/password/event failures and read-only configuration failures. Database triggers fail when the relevant value changes, rather than depending on EF's UPDATE column list.

First-user selection follows SQLite insertion order. The reversed-ID/InternalId cases expose that order in both the selected name and the updated persistent user. Initialization creates the host account name or the native fallback, assigns default permissions and the three administrator overrides, and emits no UserCreated event. POST User does not initialize a missing user. It saves the captured user before renaming and changing the password; later failures retain earlier writes.

The comparison preserves every typed persistent column and relation row, HTTP status/content type/Allow methods, lossless response values, live configuration and user events. Generated user GUIDs are mapped consistently across all relations; password hashes are checked against supplied passwords before projecting random salts. Trace IDs and Allow ordering are diagnostic. Recorded internal call names are not a production representation requirement.

The small production case-fold table is generated from actual CLR invariant case-equivalence results over BMP simple upper/lower pairs. It corrects the existing invariant lower mapping before the Node variant collator compares names. Actual controller cases cover canonical equivalence, NUL, long s, Kelvin sign, sharp s, fullwidth forms, Greek sigma and Turkish dotted/dotless i. These comparisons control whether renaming and its event occur.

Configuration mutation precedes disk persistence. The native writer emits control-character references which its reader may reject; a successful write must not be described as a successful cold read. Native CR/CRLF values remain unchanged in live configuration and normalize to LF when read from the serialized XML. The final reader test feeds every candidate configuration snapshot to the actual native XML reader and compares typed values or the corresponding read failure.

`startup-runtime.test.js` separately exercises real authentication, API keys, setup completion, fixed English responses, persisted metadata-language settings, live public/UDP/default-device server names, restart, shutdown draining, a controlled failed atomic replacement and one-row first-user selection among 20,000 unrelated users.

`startup-exchange.test.js` uses an isolated copy with the actual native schema and migration history. Candidate HTTP writes export through production exchange code; the actual native controller/user manager reads the chosen user and authenticates its password, then renames, changes the password, deletes another user and appends a user. Reimport compares all-table digests, insertion order and a candidate cold read. This is a limited database continuation, not a full-instance migration or server startup.

`provenance.json` binds the original recording, input, designated/isolated source copies, actual loaded assemblies and SQLite library, and an independent functional repeat. Complete reference-build input closure, supported-platform and two-Web acceptance remain unproven. Behavior sources include `Jellyfin.Api/Controllers/StartupController.cs`, its three DTOs, `UserManager`, the authorization handlers and native configuration/serialization classes. Applicable licensing is retained in the project LICENSE.

Run the recorder through `tools/validation/oracle.js` with the isolated .NET runtime and matching `MEDIAMANAGER_JELLYFIN_DLL`, a new output directory, absolute fixture input and `{output}/native.json`. The `read-config` mode accepts a JSON manifest of base64 configuration bytes and records actual native reader results. Preserve prior outputs and input files when extending scenarios.
