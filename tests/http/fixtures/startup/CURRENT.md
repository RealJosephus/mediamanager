# Current Startup HTTP comparison

`current-profile.json` binds the original neutral scenarios to the current Oracle source and project. Each validation run records two independent executions of the supplied designated Native runtime and compares public HTTP responses, user rows and relations, configuration values, events and failure prefixes with Node/PostgreSQL. Host account names, random user identities and password salts retain the existing consumer projections. Case-fold table layout and CLR diagnostics are not comparison targets; username changes and their events remain observable.

The same current Native XML reader consumes all Node-written configuration snapshots, including unchanged failure prefixes. Raw Native observations, Node observations and reader manifests remain in the validation output. Authentication principals, network classification and event consumers are controlled; this does not replace the separate real-authentication runtime or database-continuation tests.

The historical `native.json`, `provenance.json`, recorder and repeat identities remain unchanged. Missing historical runtime and raw recording bytes remain an archive gap and are not supplied by this current execution.
